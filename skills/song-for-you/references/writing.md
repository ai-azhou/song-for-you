# 口味、立意、结构和歌词怎么做

这里写判据和反例。字段格式看 `brief-format.md`；粘贴稿和下一步看 `suno.md`。段落标签表只在第六节写一份，所有路线都用它。

反例一律只用文字描述，不写出具体的样子；别把反例里提到的写法当成可以用的格式。这里的规则是用来做选择的，不是用来凑条件的：每一条都过了，歌也可能不好。

## 一、核材料

**熟悉程度**只表示你原本知道多少，每位歌手标一个：
- **熟悉**：你能说出这位歌手两首以上的歌，以及这些歌的编曲和人声特点。说不出就不是熟悉，宁可往低标。
- **大概知道**：知道是谁、大致什么流派，说不出具体哪首歌是什么样。
- **不认识**：原本不知道。

**来源**只填一个词：「印象」「联网」「用户补充」「无」。熟悉程度和来源是两个字段，各填各的。

**什么算查到了**：资料能说出这位歌手的声音，流派、配器、人声、律动里至少一项。只查到有这个人、发过歌，算查不到，来源填「无」。查到的和材料里的其他线索对不上，也算查不到。

**用户补充**可信度最高，和你的印象冲突时以用户为准。

**名字有几种可能**：先用材料里的歌名、合作者锁定；锁定了就照常用，说明按哪一位理解；锁不定而且锁错会改变画像才问。

**截图**：先把读到的每一行列出来给用户看；读不清的标出来，不猜；被遮住的说明没用；界面上的按钮、标题不是歌。

## 二、口味画像

**别把人压扁。** 歌手、具体哪个版本、使用场景和流派是不同的东西，不要一律压成一个流派标签。同一位歌手的歌可以跨风格；同一首歌不同版本的编曲可能完全不同。

**看到什么，就先说什么。** 歌单里某位歌手占比很高、某类版本很多，先当事实记下来，不急着解释。喜欢现场版可能是喜欢唱法、编曲、某次表演或歌手本人，不能直接写成想要现场录音的声音；要写进画像，就写具体的声音特点。

**分类是为了决定写什么，不是口味的边界。** 按「听起来是一类」分类。不硬找一个流派，也不只挑占多数的那种；几位歌手各成一派时，取共同点当主干，差别写进画像。占比很小的类可以不写歌，但在说明里提一句，不当作他不喜欢。

**写几首**：用户明说就照办；没说，或者歌是写给具体某人某事的，只写一首；其余方向交付时问一句要不要再写。`clusters` 里只放要写歌的。

每类一份画像，十项，每项一两个词或一句话：

| 字段 | 写什么 |
|---|---|
| `genre` | 流派和子流派 |
| `era` | 年代感 |
| `tempo` | 速度和律动松紧；半速感在这里说明 |
| `mode_mood` | 调式和情绪色彩 |
| `instruments` | 主要配器，各自做什么 |
| `vocal` | 性别、音色、唱法、力度；和声多少 |
| `production` | 制作质感 |
| `lyric_themes` | 这类歌常出现的情境（什么时候、什么处境） |
| `lyric_style` | 歌词的写法：口语还是书面、叙事还是态度、押韵疏密 |
| `avoid` | 这首歌不要的声音：用户明说的，加上这类歌基本不会出现的。这是制作选择，不要说成用户不喜欢 |

- 不出现真实的人名、乐队名、歌名。
- 不用换到哪类歌都成立的空泛褒义词。判据：把这一项抄到另一类画像里也说得通，就是没写具体。
- **一句话画像**（给用户看）：说他喜欢什么样的声音，不是这首新歌讲什么；让他认得出「这就是我」。

## 三、市场基底

用户想要大众能接受的歌，或者想蹭一个热门方向时，能联网就查当下的情况，不要凭印象。

查的时候分清楚：
- **哪种热**：完整收听、短视频使用、付费购买、现场，是不同的事，不能互相替代。标签播放量不等于这首歌被听了多少。
- **哪里、什么时候**：哪个地区、哪个平台、哪段时间。不同地区和平台不能相加。
- **热的是什么**：一首歌红不等于这个流派红；平台在经营一类内容也不等于听众在涨。
- **这类歌的惯例**：结构、人声、制作、歌词常写什么、最容易做成什么样的「土」或「过时」。说得出依据的才写；同一类内部差异很大时要说。

告诉用户你查到了什么、证据有多硬、哪些没查到。查不到或联网不了就直说，让他自己选方向，不编趋势。只看过摘要或一两首歌的，不要说成「能确定」「正热」。

交付时照实说：用户可能不是目标听众，他能判断缺陷和制作，「大众愿不愿意听」他的耳朵回答不了，要看真实听众的反应。用户本人不喜欢某种处理，只代表他，不要写成这类歌的通病。

## 四、立意

动笔之前答这五个问题。答不出来就不写。

| 字段 | 问题 |
|---|---|
| `type` | 这首歌是哪一类：表达态度、对一个情境做反应、讲一件有始有终的事、说一个道理。大多数歌不是讲故事；没选类型的词容易滑向流水账 |
| `one_thing` | 只说哪一件事。一句人话说得完，不是主题词 |
| `to_whom` | 对谁说。自言自语也算，但要定 |
| `moment` | 在哪一刻说 |
| `anchor` | 听众记住什么：一个反复出现的东西、一个动作，或者一句直接说出口的话。三种都可以，不是每首歌都需要一件物品 |

判据：
- 把标题去掉，别人能说出这首歌在讲哪件事吗？
- 第二段为什么不是第一段的复述？说不出来，立意还没想完。

**别写所有人第一个想到的那首。**
- 第一个想到的场景、情绪、物件和结局，通常也是所有人会想到的；第二个想到的也常常是。多想几层再选。
- 立意要从这个用户的材料里长出来：这些歌手的歌常站在什么立场、写什么处境？用户说的声音适合什么样的态度？把情节和物件换给一个口味完全不同的用户，如果还成立，就没有用上他的材料。
- 情绪立场是一种选择，不要默认。上一首用过的情节、句式和结尾方式，这一首不要再用。

**给方向时**（选择档）：2–3 个方向的处境和情绪立场都要不同，不是同一个想法换个物件。每个方向两三句：讲什么、对谁、听起来什么情绪，不写歌词，也不放进代码块。

用户说了写给谁、写什么事，就写那件事，只用他给的细节；需要虚构时，歌里的「我」是角色，不编成用户现实里的人和事。

## 五、结构

**先定目标时长。** 用户说了照用户的；没说，按这种风格完整单曲的常见长度定，拿不准取 3–4 分钟。短歌只在用户要短、或风格本来就短时才写。生成器不保证精确时长，歌词量和器乐段都会影响长度，听后再调。

**再说出这首歌的结构特点。** 排表之前先想：这种风格、这个用途的完整单曲本身通常怎么走？开头怎么进、高潮靠什么、第二段怎么处理、结尾怎么收。这首歌取哪些、不取哪些，一两句写进 `form_note`，说理由，不报流水。这种风格就该走常见骨架的，直接说是，并说为什么。

**然后排段落表。** 每段写清：

| 列 | 写什么 |
|---|---|
| 段落 | 用第六节的标签 |
| 职责 | 这一段负责什么：铺陈、蓄力、落下来、换角度、收 |
| 长度 | 大约多少行，或者是器乐段 |
| 能量 | 在这首歌内部的相对高低 |
| 这一遍有什么不同 | 重复出现的段落，这一次和上一次差在哪：词、编曲、唱法。完全一样也可以，但要是选择 |

下面这些问题用来判断，不是每条都要加一个段落：
- 高潮靠什么？
- 钩子回来的次数够不够听众记住？
- 第二段相比第一段做什么，这首歌需不需要第三段？
- 哪里喘口气？器乐段也可以放记忆点。
- 能量的最低点在哪？
- 段落长度有理由吗？主歌可以长。**副歌的每一行要么是钩子本身，要么直接托住钩子**；新信息和情节放回主歌。副歌太长时，优先让钩子重复，或者拆出副歌后的短钩子。

**副歌通常是两段。** 流行歌的副歌完整唱开时是两段，一共 8–9 行：前一段落下钩子，后一段换个说法把它推高或再落一次，最后回到钩子。第一遍副歌可以只唱前一段，4–5 行；内容完全展开的那一遍（一般是进桥段之前那一遍）要唱满两段，再进桥段。只有 4–5 行的副歌一路唱到底，整首歌会显得没唱开。

过长的段落可能让生成器赶字或漏唱，这是要听的风险，不是字数定律。同一个用户的几首歌不用同一种结构。

自带档：用户的词按他的分段；没分段就提出一种分法让他确认，不改字。

## 六、歌词

**像歌词，不像聊天，也不像散文。** 这是第一要求。读下来要讲得通，像人说的话，有能跟着唱的形状。

**动机先行。** 先想副歌里能单独哼出来的那一句：短，念出来有节奏，不靠上下文也能记住，关键词落在该拉长或该高的位置。

**重复和变化。** 先让听众认出来，再给变化，变化要有理由。
- 副歌逐字重复是常态，不是偷懒。末遍不改很正常，改不改看这首歌要什么；不要养成最后一遍才说破的习惯。
- 主歌之间可以句式相近。变化可以落在节奏、起拍、长短上，不必每句都不同。
- 整段每句都换一种形状，和整段每句一模一样，都抓不住人。

**押韵有安排。** 押韵不是每行都押，也不是不押。先想好韵脚往哪个方向走；把韵脚字单独列一遍，读得出这段在讲什么；换段可以换韵；有意留一处不押也行。不为押韵硬改语序。口语化不等于不押韵，全不押韵读起来就是聊天。

**唱得出来。** 长句要有自然气口，不把词从中间断开；空格只放在真正换气的地方，不要把词组切碎；长音和句尾尽量落在有意义的词上；中文避开容易听错的同音近音词和多音字。没有旋律之前，字调合不合你判断不了，不要说已经没有倒字问题。

**别的。** 具体的东西让人物和情境成立，但不必只有一件；可以直接说情绪，只要说得像这个人；留一处不说透常常比全讲完好。结尾怎么收也是选择，不要每首都落在同一种收法上。

**结尾的词最不能违和。** 最后几行是听众带走的，读下来要自然，像这个人在这一刻真会说的话，和前面的情境接得上。能押上韵脚就押；押不上就换个说法，不为押韵写出意思奇怪的句子。

**段落标签只用下表**，单独一行写在方括号里，段与段之间空一行：

| 用途 | 标签 |
|---|---|
| 基本段落 | `[Intro]` `[Verse]` `[Verse 1]` `[Verse 2]` `[Verse 3]` `[Pre-Chorus]` `[Chorus]` `[Final Chorus]` `[Post-Chorus]` `[Hook]` `[Bridge]` `[Outro]` |
| 能量变化 | `[Build]` `[Drop]` `[Breakdown]` |
| 器乐段 | `[Instrumental]` `[Instrumental Break]` `[Interlude]`，或「乐器名 + Solo」，乐器必须是风格描述里有的 |
| 结尾 | `[Fade Out]` `[End]` |

**演唱提示**：一个标签里最多一个。段落名、短横线、英文短语都在同一对方括号里面，右方括号是这一行的最后一个字符。提示写这一段的变化，可以是唱法，也可以是编曲；没有变化不加，不和画像冲突。
- 反例：提示放在右方括号后面，那一截会被唱出来。
- 反例：用冒号或竖线隔开；提示写中文、写小节数；一个标签里塞好几条指令；自己造表里没有的段落名。

**反例（不要这样写）**：
- 每段都能放进任何一首歌，去掉标题说不出在讲什么。
- 为了凑规则写句子：硬塞一个物件，硬把句子改得长短不一。
- 情绪全走完：从难过到释怀到祝福，一点没留；或者结尾变成一句自我和解的鸡汤。
- 为押韵把意思扭了：韵脚好看，句子讲不通。
- 用哪首歌都能套的宏大空话，或者只堆形容词加名词的意象，没有一个动作。
- 读起来像聊天记录，没有押韵，没有重复，没有形状。
- 把计划、重音记号、括号注释写进歌词。

**写完读一遍。** 只改不过关的句子。逐条核对不能代替读：读下来不像歌词，就算规则都过了也要重写。计划和记号不进交付的歌词。

## 七、风格描述

把画像翻译成生成器听得懂的话，翻译时要想这个词会被当成什么。

- 这些规则同样适用于海绵音乐的中文描述。
- 只放描述整首声音的短语：流派、情绪、配器、人声（男声还是女声要写明）、制作。少而准，要点互相竞争时删掉不重要的。
- **词义会被照字面执行。** 把每个词单独当成一条指令想一遍：照做的话会多出什么声音？暗示多人声、现场、环境声或某种年代的词，可能带来你没想要的东西；用具体声音替代。风格里和排除项里不能打架。
- 排除项写这首歌最可能跑偏的方向，几个就够，每首不一样，不要每首都排同一批。这首歌用户听后抱怨过的声音加进去。
- 段落之间的变化写在段落标签里，不写在风格描述里。

反例：
- 只堆空泛的褒义形容词，没有流派和配器。
- 把互相冲突的东西塞进一条。
- 写了像哪位歌手、哪位歌手的风格。
- 写祈使句和编排走向：要多长、哪一段撤掉什么、不要加词。

## 八、读给用户之前

- 立意五项都答了，答案是人话；第二段说得出为什么存在；用上了这个用户的材料。
- 结构表和歌词对得上；`form_note` 说得出这首歌的结构为什么这样；对用户说的结构在表里找得到。
- 用户指定的文字和标题一字没动。
- 标签都在表里，每个标签行的最后一个字符都是右方括号。
- 生成字段里没有真实名字（用户自己写的词除外，已提示）。
- 歌词读下来像歌词。
- 副歌完全展开的那一遍唱满了两段，再进桥段。
- 最后几行单独读一遍：自然，不违和，没有为押韵硬凑的句子。
